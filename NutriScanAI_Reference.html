NutriScan AI — Code Reference
A Streamlit-based food nutrition analyzer powered by a 5-agent LangGraph pipeline. Upload a food product image or enter a barcode — the system extracts nutrition data, scores it against health guidelines, and personalizes results for your health profile.
Python + Streamlit LangGraph Pipeline Groq LLM (Llama 3.1) SQLite Database Go-UPC + Open Food Facts

5-Agent Pipeline Flow

Agent 1Intake & Extraction
→
Agent 2Nutrition Lookup
→
Agent 3Health Analysis
→
Agent 4 if profilePersonalization
→
Agent 5Report Generation

Click any entry below to expand it and see a plain-English explanation of what that line or block does. Use the sidebar to jump between files. The pipeline flows top-to-bottom: image/barcode → extract → lookup → analyze → personalize → report.

def _get_score_class(score) / _get_score_label(score) / _score_colour(score)
▶
Three small helper functions that map a numeric score (1–10) to visual styling:

_get_score_class() → returns a CSS class name like "score-excellent" or "score-poor" for the score badge.
_get_score_label() → returns a human label: "Excellent", "Good", "Moderate", "Poor", or "Avoid".
_score_colour() → returns a hex color code used in scan history cards.
Scoring thresholds: 8–10 = Excellent (green), 6–8 = Good (blue), 4–6 = Moderate (orange), 2–4 = Poor (dark orange), 0–2 = Avoid (red).

state.py
NutriScanAI/state.py — LangGraph Shared State Schema
CORE
Defines the single "state dictionary" that flows through all 5 agents like a baton in a relay race. Each agent reads fields from it and writes new ones back. total=False means every field is optional — agents only populate what they know.
9–12
class NutriScanState(TypedDict, total=False):
▶
TypedDict is a Python type hint construct. It defines a dict with named, typed fields — like a struct in other languages. LangGraph uses this as the contract between agents.

total=False means all fields are optional — you don't have to provide every field when creating a state. This is important because Agent 1 can't know Agent 5's fields yet.
14–30
raw_image_bytes / barcode_number / ocr_text / nutrition_raw / extraction_confidence
▶
Agent 1 fields — populated by the Intake Agent:

raw_image_bytes — the raw image bytes uploaded by the user.
barcode_number — decoded barcode string (e.g. "8901030868702"), or None if not found.
ocr_text — raw text extracted by Tesseract OCR (used when no barcode found).
nutrition_raw — structured dict parsed from OCR (keys like energy_kcal, protein, etc.).
extraction_confidence — 0.0–1.0 score of how complete the extracted data is.
32–48
nutrition_enriched / product_image_url / nova_group / nutri_score / allergens
▶
Agent 2 fields — populated by the Nutrition Lookup Agent:

nutrition_enriched — merged dict combining OCR data + API data (API wins on conflicts).
product_image_url — product photo URL from the product database.
nova_group — 1–4 processing level (4 = ultra-processed).
nutri_score — A–E letter grade from European nutrition scoring.
allergens — list of allergens detected in the product.
50–65
health_score / consumption_frequency / red_flags / positives / health_summary
▶
Agent 3 fields — output from the Health Analysis Agent (via Groq LLM):

health_score — 1.0–10.0 general score not yet personalized.
consumption_frequency — "daily" / "a few times a week" / "weekly" / "occasional" / "avoid".
red_flags — list of specific concerns (e.g. "Sodium is 42% of daily value").
positives — list of nutritional benefits.
health_summary — 2–3 sentence plain-English summary.

graph.py
NutriScanAI/graph.py — LangGraph Pipeline Definition
PIPELINE
Builds the directed graph (DAG) that connects all 5 agents. Defines which agent runs after which, and includes one conditional branch: if the user has a health profile, route to Agent 4; otherwise skip straight to Agent 5.
28–38
def should_personalize(state): return NODE_PERSONALIZATION or NODE_REPORT
▶
This is the routing function — a conditional edge decision in LangGraph.

It reads user_profile from state. If any profile field has a value → returns the node name for Agent 4 (Personalization). If empty → jumps straight to Agent 5 (Report).
This means users without a health profile still get a full report, just without personalized warnings.
41–75
def build_graph(): graph = StateGraph(NutriScanState); graph.add_node(…); graph.add_edge(…)
▶
Constructs the LangGraph pipeline:

StateGraph(NutriScanState) — creates a new graph using our state schema.
graph.add_node(name, function) — registers each agent's run function as a named node.
graph.set_entry_point(NODE_INTAKE) — Agent 1 always runs first.
graph.add_edge(A, B) — adds a fixed connection (A always goes to B).
graph.add_conditional_edges(NODE_HEALTH, should_personalize, {…}) — adds the routing branch after Agent 3.
graph.compile() — validates the graph and prepares it for execution.
88–118
def run_pipeline(image_bytes, user_profile, manual_barcode) → NutriScanState
▶
The public function called by app.py. It:
1. Builds the initial state dict with raw_image_bytes, user_profile, and an empty pipeline_errors list.
2. If a manual barcode was typed, injects it directly into state so Agent 1 skips image processing entirely.
3. Calls nutriscan_graph.invoke(initial_state) — this runs all agents sequentially and returns the final state.
invoke() is a LangGraph method that executes the full pipeline synchronously and returns the final accumulated state.

~345–380
def _do_login(email, password): … verify_password() … st.session_state.authenticated = True
▶
Handles the login form submission:

1. Validates email format with a regex check.
2. Calls verify_password(email, password) from database.py (compares SHA-256 hash).
3. On failure: adds a 0.4 second delay (brute-force protection) and shows an error.
4. On success: sets authenticated = True, stores user info in session state, loads scan history from DB, calls st.rerun().
~437–455
def _do_forgot(email): token = create_reset_token(email); send_reset_email(email, token)
▶
Password reset flow:
1. Creates a secure random token (32 bytes URL-safe) in the database, expires in 30 minutes.
2. Sends an email with the reset link via Gmail SMTP (mailer.py).
3. Always shows the same success message whether the email exists or not — this prevents email enumeration attacks.
~510–545
def require_auth() → bool: if _handle_reset_token(): return False; …
▶
The main gate function called in app.py. Returns True if authenticated, False if not.

Priority order:
1. Check for password reset link first (intercepts before auth check).
2. If already authenticated → reload scan history from DB and return True.
3. Otherwise → render the auth page and return False.

database.py
NutriScanAI/database.py — SQLite Persistence Layer
DATABASE
Manages the SQLite database with 3 tables: users, scan_history, and reset_tokens. Uses a context manager for safe connections and WAL mode for concurrent access.
28–42
@contextmanager def _get_conn(): conn = sqlite3.connect(DB_PATH, check_same_thread=False)
▶
A Python context manager that handles the database connection lifecycle safely.

check_same_thread=False — allows the connection to be used from multiple Streamlit threads.
conn.row_factory = sqlite3.Row — makes query results accessible by column name (e.g. row["email"]) instead of index.
PRAGMA journal_mode=WAL — Write-Ahead Logging mode: safer for multiple concurrent Streamlit sessions accessing the same DB.
conn.rollback() on exception — automatically undoes any partial writes if something goes wrong.
45–90
def init_db(): conn.executescript("CREATE TABLE IF NOT EXISTS users (…)")
▶
Creates all tables on first run. CREATE TABLE IF NOT EXISTS means it's safe to call on every startup — it does nothing if tables already exist.

users table: email (unique), name, password_hash (SHA-256, NULL for Google users), avatar_url, timestamps.
scan_history table: links to user by email, stores product_name, score, frequency, barcode, the full report as JSON, timestamp.
reset_tokens table: stores password reset tokens with expiry times.
After creating tables, seeds the demo account (demo@nutriscan.ai / demo1234).
~100
def _hash(password: str) → str: return hashlib.sha256(password.encode()).hexdigest()
▶
Hashes passwords using SHA-256 before storing. This means the actual password is never saved — only its hash.

SHA-256 without salt is not considered best practice for production apps (bcrypt or Argon2 would be better), but it's acceptable for a project/demo app.
~170–200
def save_scan(email, report_data): … conn.execute("INSERT INTO scan_history …") … DELETE LIMIT
▶
Saves a scan result to the database.

First checks for duplicate: if the last scan had the same barcode, it skips insertion (prevents saving the same product twice from a double-click).
The full report_data dict is serialized to JSON and stored in the report_json column — useful for future "view full history" features.
After inserting, it prunes old entries using a subquery that keeps only the most recent 50 rows per user.
~202–240
def load_scans(email, limit=5) → list[dict]:
▶
Returns the most recent limit scans for a user, formatted for display in the sidebar.

Parses the stored ISO datetime string and reformats it to "HH:MM" for the time display and "DD Mon" for the date display.
Also deserializes the stored report_json back into a dict and includes it as report_data key for future detail view use.

AGENT 1

lookup_agent.py
NutriScanAI/agents/lookup_agent.py — Agent 2: Nutrition Lookup
AGENT 2
Looks up the product using Go-UPC to get the product name and image, then asks the Groq LLM to estimate nutrition values. If no barcode was found, uses the OCR data directly.
~100–135
def _llm_nutrition_fallback(product_name, barcode) → dict: … client.chat.completions.create(…)
▶
When no nutrition data is available from an API, this asks Groq's LLM to estimate nutrition values.

The prompt instructs the LLM to only provide values it's confident about (setting uncertain fields to null).
_repair_json(raw) handles cases where the LLM response is truncated by the token limit — it tries multiple strategies to recover a valid JSON object.
Any LLM-estimated results are marked with "llm_estimated": True so the UI can show an "AI Estimated" badge.
~50–95
def _repair_json(text) → dict: … re.sub(r',\s*"[^"]*":\s*[^,}]*$', '', text)
▶
A robust JSON repair function for handling truncated LLM output.

Strategy 1: strip markdown code fences, try direct parse.
Strategy 2: remove the last incomplete key-value pair (regex cuts off trailing incomplete JSON).
Strategy 3: try common closing characters.
Strategy 4: extract known numeric fields using regex directly from the raw text.
Returns an empty dict only if all strategies fail.
~155–175
def _flag_additives_from_text(ingredients_text) → list: re.findall(r"\b(e\d{3,4}[a-z]?)\b"…)
▶
Scans the ingredients text for E-number food additives (like E621 = MSG, E250 = sodium nitrite).

Uses a regex to find patterns like "E621", "E102", "e211", etc.
Compares found codes against a hardcoded list of concerning additives (CONCERNING_ADDITIVE_PREFIXES).
Returns a list like ["E621", "E211"] — shown as warnings in the results.

health_agent.py
NutriScanAI/agents/health_agent.py — Agent 3: Health Analysis
AGENT 3
The core AI analysis step. Sends the enriched nutrition profile to Groq (Llama 3.1) with a detailed prompt, and receives back a structured JSON health assessment: score, frequency, red flags, positives, and summary.
~65–95
def _build_health_prompt(nutrition_summary) → str: "…JSON format instructions…"
▶
The prompt tells the LLM exactly what to analyze and in what format to respond.

It specifies the scoring guide (8–10 = Excellent, etc.), tells the model to base analysis on WHO and FSSAI (Indian food safety) guidelines, and instructs it to respond with only a JSON object — no preamble, no markdown, no extra text.
Strict JSON-only instructions are critical. Without them, LLMs often add "Sure! Here's the analysis:" before the JSON, which breaks parsing.
~50–63
response = client.chat.completions.create(model=GROQ_MODEL, …); raw_text = response.choices[0].message.content
▶
Calls the Groq API with the prompt. The response structure is:

response.choices[0] — the first (and usually only) completion choice.
.message.content — the actual text the model generated.
.strip() — removes any leading/trailing whitespace from the response.
~115–135
def _parse_response(raw_text) → dict: clean = raw_text.lstrip("```json"); json.loads(clean)
▶
Parses the LLM's JSON response with graceful fallback.

Strips markdown code fences that LLMs sometimes add despite instructions.
Clamps the health score to the valid range (1.0–10.0) regardless of what the model returns.
If JSON parsing completely fails, returns safe default values so the pipeline continues without crashing.

personalization_agent.py
NutriScanAI/agents/personalization_agent.py — Agent 4: Personalization
AGENT 4
Only runs if the user has a health profile. Re-evaluates the product specifically for that user's conditions (diabetes, hypertension, etc.) and adjusts the score, frequency, and adds condition-specific warnings.
~75–110
def _build_personalization_prompt(nutrition, profile, general_analysis) → str:
▶
Builds a prompt that includes three pieces of context:

1. The product's full nutrition data.
2. The general health analysis already done by Agent 3 (score, red flags, positives).
3. The user's health profile (age, conditions like "Type 2 Diabetes", dietary restrictions, fitness goals).
The LLM's job is to re-score the product for this specific person — e.g., a product with 18g sugar rated "Good" generally might be rated "Avoid" for a diabetic user.

AGENT 5

▶
Converts the raw nutrition dict into a list of {"label", "value", "unit"} dicts — the format expected by app.py's progress bar rendering loop.

def _extract_plain_narrative(text) → str: if stripped.startswith("{"): try json.loads(stripped)

Despite being told to write flowing paragraphs, LLMs sometimes return JSON anyway. This function detects a JSON response and extracts all string values from it, joining them into a readable narrative.
Also strips any remaining markdown artifacts like triple backticks.

NutriScanAI/utils/barcode_reader.py
UTIL
Detects and decodes barcodes from images using the zxing-cpp library. Uses a 6-strategy fallback (different scales, greyscale, contrast boost) to maximize detection rate on real-world product photos.
16–55
def decode_barcode(image) → Optional[str]: … 6 attempts with different preprocessing
▶
Tries 6 different strategies to read a barcode:

1. 2x upscale + 60px white padding — fastest reliable path for most phone photos.
2. 2x greyscale + padding — handles color images that confuse the decoder.
3. 3x upscale + 80px padding — for small/low-resolution barcodes.
4. Contrast boost (2x) + padding — for faded or low-contrast barcodes.
5. Original + 60px padding only — high-res images that don't need scaling.
6. 4x upscale + 100px padding — last resort for very small barcodes.
White padding is added because barcodes need a "quiet zone" (blank space) around them to decode correctly. Tightly cropped photos often fail without it.
57–73
def _to_rgb(image) → Image: if image.mode in ("RGBA", "LA"): background.paste(image, mask=…)
▶
Converts any image mode to RGB before processing. This is critical — zxingcpp silently fails on RGBA images (it returns no results without any error).

For transparent images (RGBA), it pastes onto a white background first rather than just converting, which preserves the visual appearance correctly.

A dictionary of regex patterns for each nutrition field. Multiple patterns per field handle different label formats:

energy_kcal: matches "Energy 250 kcal", "Calories 250", "250 kcal"

The main parsing function:
1. Runs each field's regex patterns against the lowercased OCR text.
2. Converts European decimal commas to dots (e.g. "2,5g" → "2.5g").
3. Casts string values to floats.
4. Also extracts the ingredients list (text after "Ingredients:") and attempts to guess the product name from the first readable non-nutritional line.

def preprocess_for_ocr(image) → Image: greyscale → sharpen(2.5) → contrast(2.0) → UnsharpMask
▶
A 4-step image enhancement pipeline optimized for reading text from printed food labels:

convert("L") — converts to greyscale (removes color noise that confuses OCR).

def safe_agent(agent_name): def decorator(fn): @functools.wraps(fn) def wrapper(state): try: return fn(state) except Exception as e: …
▶
A decorator factory — a function that returns a decorator that wraps another function.

Usage: @safe_agent("Agent 1 (Intake)") before any agent function.
Effect: if the agent throws any exception, instead of crashing the whole pipeline, it:
— Catches the exception
— Appends a descriptive error message to state["pipeline_errors"]
— Returns the state unchanged so the next agent can still run
@functools.wraps(fn) preserves the original function's name and docstring.

▶
Validates uploaded images before sending them to the pipeline.

Checks file size (must be ≥ 1000 bytes — anything smaller is probably corrupt).
Checks the magic bytes — the first few bytes of every file that identify its format:
b'\xff\xd8\xff' = JPEG file signature
b'\x89PNG\r\n\x1a\n' = PNG file signature
b'WEBP' (at bytes 8–12) = WebP file signature
Returns a (bool, message) tuple — app.py uses this to show validation errors.

"error" — 2 or more agents failed (likely unusable results).
"warning" — some issues but results may still be valid.
"ok" — all agents completed successfully.
